Claude Opus 5：Anthropic 新一代模型亮相

这不是原文摘要，而是把文章先翻译成中文语义后，再拆成可复用的思考方式、方法论和行动线索。

1. 核心观点

原文对 Opus 5 的描述集中在三个方面：

  • 第一，它被 Anthropic 定位为更“深思熟虑且主动”的模型，接近 Claude Fable 5 的前沿智能，但价格只有一半
  • 第二，它在 Artificial Analysis 榜单上暂时领先于包括 Fable 5 在内的其他模型
  • 第三，它表现出较强的任务自驱能力。在一个机器零件建模任务中，模型无法直接查看图纸，却没有停留在“我看不到图片”的限制上，而是自行编写计算机视觉流水线，从原始像素中提取几何信息，再重建完整的 FreeCAD 三维模型。作者因此捕捉到一个重要信号：新模型的价值正在从“根据已有工具完成指令”，转向“发现缺口、创建中间工具、完成端到端目标”。

不过，文章只是引用发布说明中的一个案例，不能据此断言 Opus 5 在所有任务上都具备同等程度的主动性。

2. 关键论据

原文提供了四类证据。其一，Anthropic 的产品定位：Opus 5 被描述为以 Opus

  • 8 相同价格提供接近 Fable 5 的前沿智能，并继续提供价格为基础模型两倍的 fast mode。其二，外部排名：作者指出 Opus 5 当前位于 Artificial Analysis 榜单首位，甚至超过 Fable 5。

其三，任务案例：在不能直接查看机器零件图纸的前提下，它自主构建视觉处理管线，再生成 FreeCAD 模型，这是文章最能体现“主动工程能力”的证据。其四，网络安全测试：Opus 5 在发现漏洞方面明显增强，接近 Mythos 5，但没有接受如何利用漏洞的训练，因此在把漏洞转化为实际网络威胁方面仍明显落后。

证据结构同时包含正向能力和负向边界：模型更强，并不等于它在所有相关环节都更强；发现问题与实施攻击是两个不同能力层次。

3. 方法论

从原文可以抽象出一种评估方法。第一步，观察模型面对的真实约束，例如本案例中模型不能直接查看图纸。第二步，检查模型是否能识别约束造成的能力缺口，而不是简单报错。第三步，检查它是否能自主构造中间能力，例如编写计算机视觉流水线。第四步，检查最终产物是否真正完成目标，而不是只生成看起来合理的代码。

第五步，把相邻能力拆开评估：网络安全部分明确区分“发现漏洞”和“利用漏洞”，说明同一领域中的侦察、分析、执行可能由不同能力组成。第六步，结合成本和速度进行产品判断，因为文章同时提到基础价格与 fast mode 价格。这个方法比“模型是否聪明”更可操作：它测试模型能否在受限环境中补齐工作流，并验证每个阶段的实际结果。

4. 金句摘录

“thoughtful and proactive model”——“深思熟虑且主动的模型”：这里的主动不是多说话，而是在任务受阻时主动寻找完成路径。

“the model was intentionally given no way to directly view the drawing”——“模型被刻意设置为无法直接查看图纸”：评估重点不是给模型最舒适的工具环境，而是观察它能否在能力受限时继续推进。

“writing its own computer vision pipeline to pull the geometry from the raw pixels”——“自行编写计算机视觉流水线，从原始像素中提取几何信息”：这句话具体展示了模型如何把缺失的视觉接口转化为一个可自行实现的工程步骤。

“finding vulnerabilities” 与 “exploitation of those vulnerabilities”——“发现漏洞”与“利用漏洞”：作者借此强调，不能把一个宽泛的能力标签当作完整能力，必须区分分析、判断和实际行动。

5. 我的行动

对 deepweek：不要只让助手从事项列表中排序，而要让它在缺少信息时主动识别缺口，例如本周目标、长期目标、家庭固定事项或时间约束缺失时，先生成“需要补齐的最小信息清单”，再给出“今日上分”和“别掉血”。

对 AI Signal Radar：把每日流程拆成原始抓取、近三个月过滤、影响力筛选、正式入库和丢弃原因五个阶段，并要求 Agent 在某个阶段缺少能力时主动创建中间步骤，例如先做标题去重、再做主题聚类、再做影响力评分，而不是直接输出摘要。

对 930 前工作流 Agent 化：优先寻找那些目前依赖人工补工具、补格式、补校验的环节，验证 Agent 能否自己生成查询、脚本、转换器或检查表。对个人 IP：把“模型如何从原始输入构造完整交付链路”做成内容实验，例如给 Agent 一个客户问题，观察它是否能从资料检索、方案拆解、案例验证一直推进到公众号、小红书内容草稿。

每个实验都记录输入约束、Agent 主动增加的中间步骤、最终产物和人工返工量。

6. 第一性原理

原文案例可以还原为：目标是重建一个机器零件；直接观察图纸的能力被移除；模型仍然需要获得几何信息；于是它把“看图”重新定义为“从原始像素中提取几何”；再把视觉分析实现为自己的计算机视觉流水线；最后把结果转成 FreeCAD 模型。由此可见，工具不是固定菜单，而是可以围绕目标动态生成的中间能力。

这个原则也解释了网络安全能力的差异：发现漏洞只是完成信息分析的一部分，利用漏洞还需要额外的行动能力和风险转化链路。对于 Agent 架构，不能只问“它接了哪些工具”，还要问“目标完成需要哪些环节、哪些环节可以由 Agent 临时构造、每个环节如何验证”。

7. 真需求

原文中的“主动”具有明显的工程含义：模型发现自己无法直接查看图纸后，选择编写视觉处理管线，说明主动性必须服务于明确目标，而不是无边界地自行扩张任务。与此同时，网络安全段落表明能力边界和安全边界必须显式设计：模型可以更擅长发现漏洞，但不训练其利用漏洞，形成“分析能力增强、危险执行能力受限”的组合。

对应到用户的 Agent 工作，真正的需求是让系统能够自动补齐缺失步骤，但必须限定任务范围、工具权限、成本、输出格式和验收条件。deepweek 不能擅自替用户改变长期目标；AI Signal Radar 不能因为主动扩展检索就突破时间范围或重复入库；工作流 Agent 不能只生成代码，还要提供可审查的中间产物；

个人 IP 内容 Agent 不能把未经验证的模型判断直接包装成事实。

8. 硬核保留

以下是根据原文案例抽象出的可复用方法，不是文章逐字给出的模板。Prompt： “目标：完成【最终交付物】。已知输入：【输入内容】。明确约束：【不可直接使用的工具、信息或权限】。请先列出完成目标所必需的能力链路，并指出当前缺失的能力。对于可以在当前权限内补齐的缺口，请自行设计并执行最小中间步骤或工具。

  • 最终目标是否明确且可验收？
  • 当前限制是否被显式列出？
  • Agent 是否识别了真正的能力缺口？
  • 是否主动构造了必要的中间工具或步骤？
  • 中间产物是否可独立检查？
  • 是否区分“发现/分析”与“执行/利用”等不同能力？
  • 是否验证了最终结果，而不是只检查代码生成成功？
  • 是否记录成本、速度和人工返工量？
  • 是否限制了权限与高风险行为？
